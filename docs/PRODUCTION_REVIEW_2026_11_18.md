## P0 · 本周期数据库可用性

用量页最新快照为 04:55 的 **3.24 GB / 5 GB（64.9%）**，顶部告警需达 70%。上午 Neon 控制面读数已达 **3.57 GB（71.5%）**，还有约 **1.43 GB**，而总览顶部尚无流量告警。近两次每日用量快照之间增加 0.66 GB，包含所有来源的传输。用量页用 3.2 天样本推算约 11 月 20 日用完。按实时余额撑到重置，日均预算约 **110 MB**。将 GitHub Runner 网卡收发总量用于 Neon 归因会混入下载依赖、访问上游和探测流量。 [用量页](https://nodema-dashboard.pages.dev/#/usage) · [Neon 免费计划说明](https://neon.com/docs/introduction/plans)

1. **增加配额信号。** 顶部显示采样时间和按预算预计用尽时间，预计早于重置时提前告警。由现有可信任务低频采样，避免浏览器轮询数据库和频繁启动工作流；采样太旧时显示“读数待更新”。控制面读数仍可能滞后。
2. **先去掉无用传输。** 总览首访并发读取完整来源、机场、Sub-Store 列表，以及检测、订阅等接口；仅来源响应就约 1.35 MB。改为一个返回摘要、待处理条目和最新完整批次的接口，详细列表按页面加载。合并顶部状态条与页面重复的 `/pipeline` 读取。节点页默认列表两份响应合计约 0.68 MB；“全部状态”的前 10,000 条单页已达 3.35 MB、耗时约 5 秒，按现有实现还会并行取剩余五页。普通列表服务端分页和排序，国家/ASN 先取聚合、展开再取明细。全选仍覆盖当前筛选集，检测和导出按同一筛选快照执行。数据为应用层响应体，不能直接计为 Neon 出账。 [总览请求](../app/web/js/pages/overview.js#L179) · [节点取数](../app/web/js/pages/nodes.js#L29)
3. **给 Actions 做分阶段归因。** 定位来源同步、分片读库、收尾、接入重算和备份分别读出多少数据。优先核对 ORM 整行加载、重复读取和清理后的保留量，再决定接入任务频率和优先补测范围。下一个完整周期的验收指标是常态日均传输在剩余预算内，能看到每次异常增长关联的运行。若降耗后仍会提前耗尽，再依据实测并发与隔离恢复决定免费 PostgreSQL 迁移。提前为新鲜备份或迁移预留传输额度，额度耗尽后连 `pg_dump` 也会失去连接。 [Neon 超限行为](https://neon.com/docs/introduction/plans#what-happens-if-i-exceed-my-free-plan-limits)

- **改收尾状态。** 部分批次正确地让主工作流返回失败，也令后面的 `cleanup` 被跳过。建议显式记录分片完成、结果发布、已完成批次归档和订阅构建各阶段；给清理设置独立的成功条件，避免连续部分失败推高保留量。保持活动批次的归档保护。新版等级写回在两次实际收尾中为 **1.5 / 2.2 秒**，此前观察到的 305.9 秒退化本轮未复现。 [收尾工作流](../.github/workflows/daily-check.yml#L196)

### 三网 D 与接入证据

**1,168 / 1,646（71.0%）** 有等级节点为三网 D，涉及 277 个入口端点。12 个节点虽为三网 D，至少有一家运营商等级并非 D，符合「三网取最差」原则。另有 448 个 D 节点的端点满足通用大陆探针重复失败条件，其中 **24 个节点**在同一七天窗口、同一入口 IP 与端口上又有运营商专属探针成功记录。当前代码将通用探针的失败传入三个运营商档，并可生成“三网探针全部失败”的原因。节点页把 D 简写为“D 不通”，掩盖了单网失败、通用探针失败和证据冲突之间的差异。 [分级数据汇合](../app/probes/refresh.py#L135) · [打分规则](../app/grading.py#L279) · [节点页文案](../app/web/js/grades.js#L20)

- **改证据判定和文字。** 运营商 D 使用该运营商、该入口端点的有效样本。通用探针重复失败作为独立证据，遇明确成功标记分歧并展示时间。三网档保留最差规则，同时指出是哪一家触发 D。区分节点代理检测、入口 TCP、网段代表值以及 UDP 回包。保留现有 S/A/B 阈值，等同口径复算后观察档位分布。
- **增加覆盖原因。** 三网 B 中 58/82 个接入档缺失，已显示“接入待补测”。下一步在总览给出满足样本门槛的分母，并区分样本不足、服务拒测、CF 规则排除等状态。保留社区探针的地域和样本局限。UDP 筛选可直接显示最近回包时间和“公共 STUN/DNS”，避免用户把这项结果当作 Wi-Fi Calling 验收。

### 机场可用数量

生产机场接口将 `node_current_status` 中历史 `UP/DEGRADED` 的关联直接计为可用。以机场来源与节点的**关联**为单位，当前合计 **541 条**；其中有 102 条已从上游移除。对同一批来源关联按在来源中、节点启用、36 小时内通过的口径重算为 **0 条**。目录里的 31 个近期可用机场分类节点是另一统计范围，包含共享凭据和中转等分类。页面的“可用节点”排序和点击进入节点页都受这处口径影响。 [机场计数](../cloudflare/api-worker/src/management.ts#L123) · [页面使用](../app/web/js/pages/airports.js#L139)

- **改计算口径。** Worker、FastAPI 和页面共用“当前可用”的新鲜度和资格条件。分别展示当前可用、最近一次通过但已过期、历史关联。分组汇总用节点 ID 去重，机场订阅仍可用与其中节点最近是否测通分开展示。每日继续按当前设置测自建，机场仍按需检测。

1. **增** · 提前触发的配额告警、分阶段用量、最后完整检测及失败分片恢复状态。
