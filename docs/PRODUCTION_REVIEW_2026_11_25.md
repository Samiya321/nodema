## 节点解析、检测与分级

### 节点解析

日检的同步步骤用了 51 分 42 秒，现有日志无法拆出下载、解析和数据库各用多少时间。代码已经并行预取和按内容哈希跳过未变化的普通订阅；每轮会等预取完成再逐条应用，发生解析及入库时会调用全库命名函数，新增节点时还会重算共享凭据。优先记录预取、解析、节点及关联写回、命名与机场归类的耗时、数量和错误码。再按实测结果使用有界批次、尽早提交已完成来源，或把全库衍生计算合并到批次末尾。新兼容映射按实际出现的字段和频次选取，分别统计解析失败、运行转换不支持和真实握手失败。保留 HMAC 身份、部分成功不清理旧关联和无损转换规则。[正常批次](https://github.com/Samiya321/nodema/actions/runs/45257814772)

### 节点检测

正常批次的 40 个检测 Job 各耗时 113 至 173 秒，中位约 140 秒，时间包含 Runner 初始化。生产近 7 天用量记录 147,784 次检查尝试，其中 45,159 次至少一个阶段超时，63,752 次进入完整代理检测。超时计数按尝试，包含重试，需要按 DNS、入口 TCP、代理 HTTPS 和 UDP 分阶段统计，才能判断该调超时、重试还是改善环境隔离。

代码中手动检测与日检共用冷却和 TCP 预检跳过逻辑。手动建批成功也可能只留下冷却或预检记录。建议对少量明确选中的节点提供完整复测，仍保留运行中批次互斥、协议检查和环境故障保护。日检继续使用冷却、预检抽样、分片租约和同批次恢复。优先把检测从上游同步和归档中解耦。[检测分片日志](https://github.com/Samiya321/nodema/actions/runs/45257814772)

### 节点分级

生产三网覆盖接口抽样返回 1,592 个符合当前可用范围的节点，1,302 个有接入档，6 个按落地规则排除。有接入档的计数来自生产旧口径，包含网段等参考证据。最近完整批次的分级步骤约 21 秒。

`0027_node_observations` 加入端点证据、样本条件和三网短板，但仍以首个 IPv4 和配置端口选端点。检测把 DNS 地址列表交给 Mihomo；首个地址可能与实际连接不同。用两个合成地址复核，在检测天数与探针样本完全相同的条件下，只交换 DNS 列表顺序，电信档从 D 变为 A。这个复现适用于待发布的 `0027`，生产多地址节点受影响数量待核对。

发布前明确区分 DNS 候选、TCP 预检命中和实际代理连接。只有确定的 IP 和端口才用于节点级端点确认。地址不明确时保留参考档，避免单一候选地址的失败或成功外推到整个节点。用同一份隔离数据比较新旧等级迁移、各运营商覆盖和成品候选变化，再决定测量预算是否要调整。优先修证据口径，保留当前 RTT、丢包和可用率阈值。[分级设计](NODE_GRADING_DESIGN.md) · [重算步骤](https://github.com/Samiya321/nodema/actions/runs/45257814772)

## 本地已完成的登录改动

管理员密钥只在登录请求的 Authorization 头中传一次。Worker 在连接数据库之前签发 8 小时的同源会话，使用 `Secure`、`HttpOnly`、`SameSite=Strict` 的 Cookie，Cookie 不保存管理员密钥。刷新先查会话，退出清除本浏览器的 Cookie 并通知同源已打开的标签页。Cookie 鉴权的写操作要求 Origin 精确匹配。外部管理 API 保留 Bearer，巡检 token 范围仍为 heartbeat。签名会话无服务器会话表，退出清除浏览器里的值，已被复制的值按自身到期时间失效。

本地改动基于 `9a07936`，所在分支包含尚未发布的 `0027_node_observations`。会话功能本身无需迁移、新 Secret 或新服务。独立发布时应将鉴权改动移到兼容生产 `0026_maintenance` 的分支，先发布 Worker，再发布 Pages。现网仍使用原登录。验证范围见 [状态记录](STATUS.md)。
